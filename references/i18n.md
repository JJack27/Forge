# Internationalization (i18n)

The book supports multiple languages via **parallel sibling folders** — `en/`, `zh/`, etc. — each a complete, independent copy of the book in one language. Switching language is just a hyperlink click: every page has a `<a class="lang-toggle" href="../other-lang/…">` link in the topbar that jumps to the parallel file in the other folder. No runtime switcher, no `fetch()`, no re-render.

Per the learner's choices at Stage 0.5: the book is built end-to-end in the **primary language first** (the language they're chatting in), delivered, and only then translated into the other selected languages as a follow-up step (Stage 4.5).

## The i18n invariant

**The HTML structure is identical across language folders, except for translated prose.** Concretely, for each chapter `<primary-lang>/0N-slug.html` there is a `<other-lang>/0N-slug.html` with:

- The **same filename** (so the `lang-toggle` link is predictable).
- The **same section ids** (`id="sec-…"` values appear unchanged in both languages). Anchors are language-neutral.
- The **same number of test questions**, same types in the same order, same `data-review` anchors.
- The **same `data-correct` arrays** (mcq scoring tokens like `["b"]`, `["a","c"]`) — byte-identical across languages.
- The **same `data-accepted` arrays for code-symbol answers** (`["ungoogled-chromium"]`, `["iframe"]`, `["[native code]"]`). ONLY translate `accepted` if the answer is a natural-language word a reader of the new language would type in that language.
- The **same `data-key-points` count** (translate each point's text; keep the array length identical).
- The **same `window.BOOK_CONFIG`** script block — except flip `lang: "en"` to `lang: "zh"` (or whichever) so `localStorage` keys namespace per language.
- The **same SVG diagrams** (same `viewBox`, same shapes, same coordinates) — only the `<text>` content inside the SVG and the `<figcaption>` below it get translated.

This is what makes the book work as a unit: a learner can pass the English test, switch to Chinese, and find the same chapter with the same structure in the same order, just in another language. Their progress is tracked per language (`localStorage` keys differ by the `lang` field).

## The language toggle

Every page has a link in the topbar:

```html
<a class="lang-toggle" href="../zh/01-…html">中文 →</a>
```

On the primary-language pages it points at the corresponding file in the other folder; on the other-language pages it points back (`href="../en/01-…html"` with text like `→ English`). The link text on each page is in the **target** language (so a reader of either language sees the toggle labeled with the other language's name).

## What gets translated, what doesn't

| Translate to the new language | Do NOT translate |
|---|---|
| Chapter title, eyebrow, lede, objectives | `<html lang="…">` (but flip to the new code) |
| Body prose: `<p>`, `<h2>`/`<h3>` heading text, `<li>`, `<td>`, `<figcaption>` | HTML tags, attributes, class names, ids |
| `<div class="box">` content | Section ids (`id="sec-…"` — language-neutral anchors) |
| `<pre><code>` **comments only** (if prose-y) | Code inside `<pre><code>` (the code itself; identifiers; output) |
| Test `prompt`, `options[].label` prose | File paths, line numbers, API names, library names |
| `data-answer`, `data-rationale` prose | `data-correct` (mcq scoring tokens — byte-identical) |
| `data-key-points` array (translate each point) | `data-accepted` for code-symbol answers (byte-identical) |
| SVG `<text>` content + `<figcaption>` | SVG `viewBox`, coordinates, shapes, `style="fill:var(--…)"` attributes |
| Topbar crumb, lang-toggle link text | `data-review` values (section ids — language-neutral) |
| `window.BOOK_CONFIG.lang` (flip to the new code) | The rest of `window.BOOK_CONFIG` (slug, chapters list — byte-identical) |
| | The `<head>` theme `<script>` snippet (copy verbatim — it is language-neutral) |

**Special cases:**

- **Technical terms stay in English** in the new language's prose (e.g. in Chinese technical writing, keep `fingerprint`, `WebGL`, `TLS`, `CDP`, `Blink`, `getFarbleSeed64`, patch filenames, file paths). You MAY add a parenthetical gloss on first appearance (`realm（执行环境）`) but keep the English term. This is the convention for expert/professional readers in most non-English tech communities.
- **`accepted` for fill questions:** if the answer is a code symbol or API name (`Vec::push`, `kFromDebugger`, `ungoogled-chromium`), keep it byte-identical — a reader of any language types it verbatim. If the answer is a natural-language word ("ownership", "the environment"), translate the acceptable forms so the reader can type in their language, and keep the original-language forms too (superset, not replacement).
- **`<pre><code>` blocks:** preserve verbatim across languages. A Rust/C++/JS snippet is the same in English and Chinese. Only translate comments inside the code if they're prose-y and would otherwise confuse; often it's clearer to leave them.

## Translation workflow (Stage 4.5)

For each additional selected language, after the primary-language book is approved:

1. **Copy the entire primary folder** → new folder: `cp -r en/ zh/` (or whatever the language code is).
2. **Copy the `assets/` subfolder verbatim.** `book.js` and `style.css` are identical across languages. Do not edit them per-language.
3. **For each chapter HTML file in the new folder:**
   - Translate the prose per the table above.
   - Change `<html lang="en">` → `<html lang="zh-CN">` (or the appropriate code).
   - Flip the `lang-toggle` link: `href="../zh/…"` → `href="../en/…"` (points back at the primary), and change the text from `中文 →` to `→ English` (or the appropriate pair).
   - In the inline `window.BOOK_CONFIG` block, flip `lang: "en"` → `lang: "zh"`. Leave `slug` and `chapters` unchanged.
4. **Do the same for `index.html`** in the new folder (translate the dashboard title/subtitle, flip `lang` and the `lang-toggle`).
5. **Verify the invariant** (see below).
6. Tell the learner the language is ready and ask whether to continue to the next selected language.

## Translation tips

- **Preserve code blocks verbatim.** A snippet is the same in every language. Only translate comments inside code if they're prose-y; otherwise leave them.
- **Don't translate proper nouns, project names, or API names.** "PostgreSQL", "React", `useState`, "Borrow checker" (often left untranslated in Chinese tech writing).
- **Keep markup identical.** If a chapter's bodyHtml has `<p>…</p><section id="sec-x"><h3>…</h3></section>`, the translated version has the same tags and the same id, just different text inside.
- **Translate meaning, not words.** A scenario question about "the borrow checker rejecting this code" should become a natural scenario question in the target language, not a word-by-word gloss.
- **Keep the test difficulty identical.** If the primary version of a question is tricky, the translated version should be equally tricky — don't accidentally make it easier or harder by simplifying the wording.
- **Watch for the JSON-in-attribute pitfall.** When translating inside `data-answer`, `data-rationale`, `data-key-points` attribute values: the attribute is wrapped in double quotes (`data-answer="…"`), so any `"` you put inside the translated text breaks the HTML. Use `&quot;` or single quotes (`「」`, `''`) inside the value, or rephrase to avoid the quote character.

## localStorage namespacing

Scores are stored per language: `book:<slug>:<lang>:ch:<n>`. The `<lang>` comes from `window.BOOK_CONFIG.lang` on each page, which is why the primary and translated folders MUST have different `lang` values. A learner who passes the English chapter 3 test but hasn't taken the Chinese one will see English chapter 3 as ✓ and Chinese chapter 3 as ○. This is intentional — passing a test in one language doesn't certify you in another.

## Verifying the i18n invariant

After translating, run this from the project root to check every chapter has the same structure across languages:

```bash
primary="en"   # change to your primary language code
for other in */; do
  other="${other%/}"
  [ "$other" = "$primary" ] && continue
  [ -d "$other" ] || continue
  for pf in "$primary"/0*.html; do
    [ -f "$pf" ] || continue
    fname=$(basename "$pf")
    of="$other/$fname"
    [ -f "$of" ] || { echo "MISSING translated file: $of"; continue; }
    # 1. Same question count
    pq=$(grep -c 'class="q"' "$pf")
    oq=$(grep -c 'class="q"' "$of")
    [ "$pq" = "$oq" ] || echo "Q-COUNT MISMATCH $fname: $primary=$pq $other=$oq"
    # 2. Same section ids
    pids=$(grep -oE 'id="sec-[a-z0-9-]+"' "$pf" | sort -u)
    oids=$(grep -oE 'id="sec-[a-z0-9-]+"' "$of" | sort -u)
    [ "$pids" = "$oids" ] || echo "SECTION-ID MISMATCH in $fname"
    # 3. Same data-correct arrays (in order)
    pcorr=$(grep -oE 'data-correct=("[^"]*"|'"'"'[^'"'"']*'"'"')' "$pf")
    ocorr=$(grep -oE 'data-correct=("[^"]*"|'"'"'[^'"'"']*'"'"')' "$of")
    [ "$pcorr" = "$ocorr" ] || echo "DATA-CORRECT MISMATCH in $fname"
    # 4. Same data-review anchors (in order)
    prev=$(grep -oE 'data-review="sec-[a-z0-9-]+"' "$pf")
    orev=$(grep -oE 'data-review="sec-[a-z0-9-]+"' "$of")
    [ "$prev" = "$orev" ] || echo "DATA-REVIEW MISMATCH in $fname"
    # 5. lang attribute is correct per folder
    grep -q "<html lang=\"$other\"" "$of" 2>/dev/null || grep -q "<html lang=\"${other}-" "$of" 2>/dev/null \
      || echo "LANG ATTR WRONG in $of (expected $other or ${other}-*)"
  done
done
```

If this script is silent, the invariant holds.
